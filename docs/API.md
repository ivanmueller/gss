# 7. HTTP API contract (v1)

API prefix: `/api/v1`. JSON request/response with consistent envelope and UTC ISO 8601 timestamps. Authenticate every private endpoint; resolve and verify tenant membership per request. Server cannot trust `organization_id`, prices, roles, or margins supplied by a browser. Requests may accept an organization selector but must authorize it.

### Implemented so far

| Method/path | Notes |
|---|---|
| `GET /api/v1/health` | Public liveness probe. |
| `GET /api/v1/me` | The verified user and their active organizations with roles. |
| `GET /api/v1/counterparties?organization_id=` | Counterparties visible to the user (up to 5,000, with `truncated`), with contact and location counts, regions, logo checksum, `archivedAt` (archived ones included; the web app hides them unless asked), and `buys` and `sells` (commodity codes, for the commodity filter). |
| `GET /api/v1/counterparties/{id}` | One counterparty with contacts and facilities; 404 when missing or not visible to the user (for example a suspended member). The counterparty and each contact and facility carry a `version` (last change time to the microsecond, e.g. `2026-10-28T14:05:09.123456Z`); facilities also carry `geocodingSource`. The counterparty also carries `website` (or null), `notes` and `commodities` (`{ code, name, direction }`, buys first, in the commodity list's order). The list and each counterparty also carry `equipment` (a carrier's, `EQUIPMENT` in `@grain/domain`), `lanes` (`{ origin, destination, transport }` as entered) and `quotedLanes` (the provinces and states its freight rates run between, withdrawn and expired ones too, truck and rail together as `rail_and_truck`; derived, never stored; 2026-11-01). `PATCH /api/v1/counterparties/{id}` takes an optional `equipment` list beside `values`; left out, the equipment is kept. |
| `GET /api/v1/members?organization_id=` | The organization's members with email, first and last name, role, status, joined time, `version` and `isYou`. Admins only (403 otherwise). |

Admins only. |

| `PATCH /api/v1/members/{id}` | Body: `organizationId`, `version`, and any of `role`, `status` (`active` or `suspended`), `firstName`, `lastName` (empty or null removes a name). 409 `RECORD_CHANGED`; 409 `OWN_MEMBERSHIP` for an admin's own role or status; 409 `LAST_ADMIN` when the organization would have no active admin. | `POST /api/v1/counterparties/{id}/contacts`, `PATCH`/`DELETE .../contacts/{contactId}` | Adds, corrects (body `version`, `values`) or removes a contact; answers the counterparty. Operations/Admin. |
| `PATCH /api/v1/counterparties/{id}/lanes` | A carrier's lanes (owner's request, 2026-11-01). Body `{ add, remove }`: `add` a list of `{ origin, destination, transport }`, `remove` a list of `{ origin, destination }`; places are ISO 3166-2 codes of Canada's provinces and territories and the U.S. states and DC (`CA-AB`, `US-MT`; `LANE_REGIONS` in `@grain/domain`), `transport` is `truck`, `rail`, `rail_and_truck` or null when not stated (2026-11-01); at most 500 each. Traders, operations and admins. |
| `PATCH /api/v1/counterparties/{id}/commodities` | Body `{ add, remove, verify }` (`verify` optional), each a list of `{ commodity, direction }` (one of the 20 commodity codes; `buys` or `sells`); one added is verified by the person adding it; `verify` verifies listed unverified ones (from a spreadsheet) in the person's name; adding one already listed, removing one not listed or verifying one already verified changes nothing; each commodity on the counterparty carries `verifiedAt` (null while unverified); answers the counterparty. 404 out of reach, 409 `ARCHIVED`, 422 for a code off the list or an empty change. | `PUT /api/v1/counterparties/{id}/main-contact` | Body `{ contactId }`: makes one of its contacts the main contact (any other stops being it), or none with `null`; answers the counterparty, whose contacts carry `isMain` (the main contact listed first). 404 for a contact of another counterparty or organization, 409 `ARCHIVED`. | `GET /api/v1/counterparties/{id}/logo` | The PNG logo (`image/png`, `nosniff`, sandboxing CSP, ETag). | `POST /api/v1/facilities/geocode` | Body: `organizationId`, and optionally `counterpartyId` (one counterparty's locations: after adding it by hand, or from its page) or `importBatchId` (one import's), not both. Since 2026-11-04 one page of 100 locations (`GEOCODE_PAGE`) in id order per request: optional `after` (the previous answer's `next`) asks for the following page; the answer's `next` is null when none are left. |

The summary adds `lanes` and `addedLanes`, each company `lanes`. Operations/Admin.. A row's values never include a contact's fields (refused with 422): a file adds and changes no contacts, which are added on the counterparty's page (owner's request, 2026-11-03). |

| `POST /api/v1/telnyx/voice` | Telnyx's call events (the Voice API application's webhook URL). No sign-in: the `telnyx-signature-ed25519` header must be Telnyx's Ed25519 signature of `<telnyx-timestamp>\|<raw body>` under `TELNYX_PUBLIC_KEY`, with the timestamp within five minutes, or 401 `BAD_SIGNATURE` before anything is read. `call.initiated`, `call.answered`, `call.gather.ended` and `call.hangup` of the platform's calls (found by their `client_state`) are kept once by event id and applied as the person who placed the call; the commands that follow (ask for 1, dial them, hang up a leg) are kept as pending with the event, claimed under the call's lock and sent only if the call still wants them; when Telnyx cannot be reached the answer is 500, and while another delivery holds a claim made in the last 30 seconds it is 503 `COMMAND_IN_FLIGHT`, so that the event's next delivery sends them; only the latest claim's completion counts, and a hang-up an outcome calls for is kept as a command too. A delivery answers 200 only when every command of the call is settled; a timeout (every request to Telnyx gives up after 10 seconds), 429 or 5xx from Telnyx is retried, not given up. For a call whose caller was suspended or removed, every leg it knows of is hung up at Telnyx before the event is acknowledged. A late `call.answered` from their known leg, before the end, makes an ended call that was dialed to them talked; a leg that starts or answers after the end is hung up. `call.recording.saved` and `call.recording.transcription.saved` keep a call's recording and transcript (500 when they cannot, so Telnyx sends them again). Other events answer 200 and change nothing. A call to GSS's number that the platform did not place is rejected with a busy signal (callbacks come later). 500 when the database fails, so Telnyx sends the event again. |

Every response has an `X-Request-Id` header; writes record it in the audit trail.

Edits answer `422 VALIDATION_FAILED` with `issues` (each a `field`, one of the import's field ids or null, and a `message`), `404` for a record that is missing or not visible to the user, `403` for a member who may not edit, `409 RECORD_CHANGED` when the `version` is no longer current, `409 ARCHIVED` for an archived counterparty and `409 DUPLICATE_NAME` when another counterparty in the organization has the legal name in that country (ignoring case), and removing a location with bids or offers answers `409 LOCATION_HAS_QUOTES`, one where freight rates start or end `409 LOCATION_HAS_FREIGHT`. Each edit first locks its counterparty, so archiving and an edit under it happen one after the other and an edit never lands on a counterparty archived meanwhile. Edits are never retried by the API when the connection is lost.
