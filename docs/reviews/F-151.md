## Escalated to the owner

**What is settled.** The repair #194 needs is done and verified by Codex: the Merge policy runs main's current rules, never a pull request's fork point or base branch (D1-01, verified in round 1), and the withdrawal reads every open pull request (R1-02, verified in round 2).

**What is not.** D1-02, a narrow window when the merge rules themselves change: a pull request that passed under the old rules could still merge under them if automatic merging is turned on for it in the minutes between a rules change's approval and its merge. F-151 narrows it three ways (withdrawal before the merge, withdrawal after it, the merge guard refusing automatic merging while a rules change is open); Codex's remaining case needs another, older Claude session acting in that window. Codex wants GitHub itself to enforce freshness ("require branches to be up to date"), which would also force a new Codex review after every update from main: more infrastructure than this repair.

**Decision for the owner:** accept this narrow window for rules changes (rare, governance-only, each approved by the owner) and merge F-151; or ask for the GitHub-enforced version as separate work.
