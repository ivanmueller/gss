## How staging is wired

- **App and API:** one Cloudflare Worker, `grain-trading-api-staging`, at https://grain-trading-api-staging.ivan-mueller02.workers.dev. It serves `apps/web/dist` and `/api/v1/*`, and deploys from GitHub Actions on every merge to `main`.
- **Database:** Supabase project `gss-staging` (ref `nfwizbcpjpqxdoojfbdr`, free plan) holds the owner's real data. Merges apply migrations with `supabase db push` (GitHub secret `SUPABASE_STAGING_DB_URL`).
- **Worker → database:** through the Hyperdrive binding `HYPERDRIVE`, configuration `gss-staging` (id `bbc915879c6848abaa08605ff7d7825c`):
  - verifies TLS (`verify-full`) against Supabase's root CA (`supabase/certs/`);
  - connects to the session pooler on port 5432 as `app_api.nfwizbcpjpqxdoojfbdr`;
  - has query caching off and at most 5 origin connections.

  It is created or updated by the manual workflow **Set up Hyperdrive (staging)** from the GitHub secret `SUPABASE_HYPERDRIVE_URL`. Direct connections from the Worker fail, because the Workers runtime cannot trust Supabase's private CA.
- **Cloudflare API token** (GitHub secret `CLOUDFLARE_API_TOKEN`): needs Workers edit, Hyperdrive edit, and SSL and Certificates edit.
- **Logs:** Workers Logs are on (`observability` in `apps/api/wrangler.jsonc`). Database failures log a secret-free `code=… kind=…` line with the request id.
- **People:** the owner is an admin (`org_admin`) of GSS, the one organization. Admins add people on the **Team** page; the Worker makes their logins through Supabase Auth's admin API with the Worker secret `SUPABASE_SECRET_KEY` (README, Sign-in). Names are set on the Team page or by the person at first sign-in.
- **Scheduled job:** the Worker's cron triggers `15 14,22 * * *` (UTC, `apps/api/wrangler.jsonc`) fetch the Bank of Canada's USD/CAD rate; its log line starts "Bank of Canada USD/CAD" (README, "Exchange rate"). No secret is needed. A second trigger, `*/2 * * * *`, has Telnyx transcribe new call recordings by side and deletes their audio 24 hours after the call (README, "Calling through Telnyx").
- **Worker secrets:** `GEOCODIO_API_KEY` (set by the owner), `SUPABASE_SECRET_KEY` (added by the owner on 2026-10-28; making a login from the Team page on staging not yet confirmed), and `TELNYX_API_KEY`, `TELNYX_PUBLIC_KEY`, `TELNYX_CONNECTION_ID`, `TELNYX_PHONE_NUMBER` (added by the owner on 2026-11-02, all of type Secret so that deploys keep them). Telnyx: one Canadian number, an Outbound Voice Profile (Canada and the U.S.), a Voice API application `GSS-app` with webhook `…/api/v1/telnyx/voice` (API v2) and a messaging profile with webhook `…/api/v1/telnyx/messaging` (not built yet), set up by the owner on a trial account, upgraded to a paid account by the owner (reported 2026-11-05, `docs/DECISIONS.md`). The `app_api` password is set by SQL on `gss-staging` and never committed.
